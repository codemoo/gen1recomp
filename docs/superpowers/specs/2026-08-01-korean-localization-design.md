## 1. 목표와 제약

**gen1recomp 을 한국어로 플레이한다.** 1차 목표는 개인 빌드지만, **모든 작업물은 업스트림에
제출 가능한 형태로 만든다.** 이 제약이 아래 모든 결정을 지배한다.

| | 결정 | 근거 |
|---|---|---|
| 배포 단위 | **콘텐츠 모드 + 독립된 엔진 패치 6종** (포크 아님) | 번역 인프라가 이미 존재한다 (PR #311, #450) |
| 글리프 | **8px 폭 × 16px 높이**, Galmuri11 Condensed (SIL OFL), base `0x100` | 실측 결과 8x8 은 받침 혼동(은/온, 생/썽), 16x16 은 줄당 9자로 반토막. 8x16 만이 **줄당 18자를 유지하면서** 가독성을 얻는다. 정식 한국어판 포켓몬스터 금·은이 동일 화면에서 택한 방식 |
| 번역 생산 | 고유명사 선(先)확정 → 대사 배치 번역 + 검수 | 고유명사는 창작 대상이 아니라 조회 대상 |
| 기존 팬패치 | **용어 참고로만.** 텍스트 추출 안 함 | 라이선스 미표기 → 업스트림 제출 불가. 품질도 영문 중역이라 낮음 |

### 명시적 비목표

- pret 디스어셈블리(`pokered`/`pokeyellow`) 수정 — ROM 공급원일 뿐 손대지 않는다
- 실기 `.sav` 한글 이름 왕복 — Gen 1/2 ROM 바이트 인코딩에 한글 코드포인트가 없다
- 타이틀/엔딩 등 **이미지로 구워진** 텍스트 — 4단계로 미룬다

## 4. 엔진 패치 6종

각각 독립 브랜치 = 독립 PR. 전부 현재 리비전에서 **필요함이 재확인됐다.**

### P1 — `Font.lua` 페이지별 셀 높이 (`cellH`)

`src/render/Font.lua:14` 의 `local GLYPH = 8` 이 quad 의 **폭이자 높이**로 쓰여
(`:46-50`), 8px 이 아닌 셀은 엔진에 표현할 방법 자체가 없다.

```lua
local cellH = page.cellH or GLYPH
newQuad((i % perRow) * GLYPH, floor(i/perRow) * cellH, GLYPH, cellH, iw, ih)
```

`Font.drawCode` 에서 `y - (page.cellH - GLYPH)` 로 보정해 **베이스라인을 유지**한다. 이렇게
하면 글리프가 위로 자라므로 호출부는 손대지 않는다. 바닐라 페이지는 `cellH == 8` 이라
오프셋이 0 — 영문 출력은 바이트 동일.

- **모든 글리프가 `Font.drawCode` 한 곳을 통과한다** (`Font.draw` → `:217`,
  `Font.drawBox` → `:238-248`). 단일 지점 수정으로 충분하다.
- 스키마 변경: `src/mods/Schemas.lua` 의 `R.font` 에 `cellH` 추가

**⭐ 업스트림 가치:** 일본어(#245)·중국어도 동일한 제약을 받는다. 한국어 전용이 아니라
**비라틴 문자 전반을 여는 공용 수정**이다.

### P2 — modkit `translation` 버그 5종 + 테스트

`tools/modkit.py` 의 번역 스캐폴더. **버그 4개 전부 현 리비전에 살아있고, 5번째가 추가
발견됐다.** 전부 **스캐폴드 직후에는 터지지 않고 번역자가 작업을 시작한 뒤에 터진다.**

| # | 위치 | 증상 |
|---|---|---|
| 1 | `modkit.py:1518` | `mod.hooks:on(...)` 생성 — API 에는 `wrap` 만 존재 (`Loader.lua:559-561`). 실행 시 `attempt to call method 'on'` → **번역 모드 전체가 롤백**. `lang/naming.lua` 를 채우는 순간 발동 |
| 1b | `modkit.py:1520` | **신규 발견.** `on`→`wrap` 으로 고쳐도 시그니처가 틀림. wrap 콜백은 `(next, base, ctx)` 로 호출되는데(`Hooks.lua:66`) 스텁은 `(base, ctx)` 로 선언 — 인자가 한 칸씩 밀린다 |
| 2 | `modkit.py:1841`, `:1579` | 폰트 경로 `assets/font/*.png` 는 `Assets.resolve` 가 재작성하지 않고(`Assets.lua:37`), `Font.load` 는 pcall 로 조용히 스킵(`Font.lua:43`). **글자가 안 나오는데 로그도 없다** |
| 3 | 쓰기 `:1917` / 읽기 `:1887` | orphan 을 `--   [key] = ...` 주석으로 park 하는데 리더 정규식이 `^\s*\[` 라 못 읽음 → **두 번째 `--refresh` 가 보류 번역을 삭제** |
| 4 | `modkit.py:1784` | `TRANSLATING.md` 를 `overwrite=True` 로 재생성 → **번역자 메모 파괴**. 이웃 라인들은 `overwrite=not exists` 인데 이 줄만 다름 |

**원인은 명확하다: `grep -n translation tests/modkit_tests.lua` 가 0건.** 685줄짜리
테스트 파일이 scaffold/validate/pack/lint 만 다루고 `translation` 은 전혀 건드리지 않는다.
**버그 수정보다 테스트 추가가 더 큰 작업이고, 그게 이 PR 의 본체다.**

### P4 — 세로 8px 피치 화면 재배치

호출부 실측: `Font.draw` **287곳**, `Font.drawCode` **69곳**, `Font.drawBox` 54곳.

> **`tools/save-editor/` 는 범위 밖이다.** `src.render.Font` 를 아예 require 하지 않는
> LÖVE 네이티브 UI 다 (`Theme.lua:304` 의 `G.newFont`). 이전 조사에서 "세이브 에디터도
> 폰트 문제" 라고 한 것은 **틀렸다** — 별개 이슈이며 이 패치와 무관하다.

16px 글리프가 위로 자라므로, **위쪽 8px 밴드가 점유된 행**이 충돌한다. 대화상자는
104–111 / 120–127 행이 비어 있어 안전하다. 충돌하는 화면과 스크롤 상수는 220개 사이트
목록으로 확보돼 있다.

절대 밀리면 안 되는 것: 테두리 타일, 커서/화살표 글리프, HUD 타일. 이들은 `cellH == 8`
페이지에서 해결되므로 오프셋이 0이 되어 자동으로 안전하다.

### P5 — 조사(josa) 자동 선택

`src/core/Strings.lua:112` 에 **`string.format` 이 전체 로컬라이제이션 계층에서 딱 하나**
있다. 여기가 삽입점이다.

번역자가 카탈로그에 마커를 쓰고, **보간 이후** 앞 음절의 받침을 보고 해소한다:

```lua
-- "야생 %s{이/가}\n나타났다!" → "야생 리자몽이..." / "야생 피카츄가..."
-- (code - 0xAC00) % 28 == 0  →  받침 없음
```

`이/가`, `은/는`, `을/를`, `와/과`, `(으)로` 를 다룬다. `(으)로` 는 **ㄹ 받침(jong == 8)
예외**가 있어 3분기다. 라틴 문자·숫자로 끝나는 이름도 발음 기준으로 처리한다
(`BILL이`, `7로` vs `3으로`).

**같이 해결해야 하는 제약:** LuaJIT `string.format` 에 위치 지정자(`%1$s`)가 없다.
**인자 2개 이상 템플릿이 82곳**이라 한국어 어순 재배치가 불가능하다. 실제 오역 사례:

- `RomImporter.lua:4114` `"%d of %d enabled"` → 한국어는 "6개 중 3개" 인데 "3개 중 6개" 가 됨
- `MoveLearnMenu.lua:47/117` — 1번 인자가 3번 위치에 **반복** 등장. 한국어에서 이름을
  영어와 똑같은 횟수로 반복해야 함

→ 위치 지정 shim 을 P5 에 포함한다. **없으면 부분 로컬라이제이션에 그친다.**

> 함정: 지금 번역자가 `%1$s` 를 쓰면 **경고 없이 영어가 나온다.** arity 가드는 통과하고
> `string.format` 이 던진 에러를 `Strings.lua:113` 의 pcall 이 삼킨다. 이 pcall 은 어떤
> 포맷 에러든 조용히 먹으므로 로그를 추가한다.

## 5. 이름 입력 화면

공식 한국어 골드·실버 방식을 그대로 따른다:

> 자모 자판만 표시 (문자셋 전환·Shift 없음, 한 화면에 전부). 자음 19(단자음 14 + 쌍자음 5),
> 모음 21(단모음 10 + 복합모음 11), 4행. **입력 즉시 조합** — 모음을 누르면 앞 자음과 합쳐져
> 초성+중성이 되고, 자음은 앞 블록에 받침이 없으면 종성으로 붙는다. 못 붙고 자리가 남으면
> 독립 자모로 들어간다.

`NamingScreen.lua:99` 의 `table.concat(self.glyphs)` 는 고른 칸을 이어붙일 뿐이라
조합기가 없다. `ui.naming.grid` 훅은 격자만 교체하므로 부족하다.

→ **`screens` 레지스트리로 `NamingScreen` 자체를 교체한다. 모드 쪽 작업이며 엔진 PR 이
아니다.**

> 조합형을 **런타임 렌더링**에 쓰는 것은 불가능하다 — charmap 이 "바이트 시퀀스 → 글리프
> 코드 **1개**" 로 고정이라(`Font.lua:130, :182`) 한 음절이 여러 번 그려질 수 없다.
> 조합은 **입력기**에서만 일어나고, 결과는 완성형 음절 1개다.

## 6. 폰트 시트

- **Galmuri11 Condensed** @ 12ppem → 한글 advance 정확히 8px, 셀 16px
- base `0x100` (문서상 자유 영역), **완성형 11,172자 전체**
- 시트 1024×1408, PNG ~150KB. 모든 배포 타겟의 텍스처 한도 안

전체를 넣는 이유: 번역자가 시트에 없는 음절을 쓰면 `Font.encode` 가 **공백으로 대체**해
조용히 사라진다. 용량이 문제가 안 되므로 원천 차단한다.

**성능 주의:** charmap 은 첫 바이트로 버킷팅 후 **선형 스캔**이고, 한글은 `0xEA`–`0xED`
4개 버킷에 몰린다. `Font.split` 은 캐시 없이 매 `Font.draw`/`Font.width` 마다 돈다.
측정값은 서브밀리초지만, **정확 일치 해시 fast-path** 를 선형 스캔 앞에 두는 것이 진짜 해법이다.

## 7. 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **0** | P2(+테스트), P6, 게이트 조이기. 폰트 시트 생성 | 스캐폴더가 번역자를 배신하지 않는다 |

> 그 결과가 2단계 이후를 바꿀 수 있다 (예: 글리프 기하 재검토). 2–4단계는 그때 다시 계획한다.

## 9. 남은 위험

1. **8x16 실기 가독성** — 4x 렌더로는 충분히 읽히지만 RG34XXSP 실물 패널과 폰에서
   확인한 사람이 없다. 1단계에서 최우선 확인
2. **업스트림 수용 여부** — #245(일본어)에 오너가 "간단하진 않지만 목록에 있다" 고 답했다.
   일본어도 같은 `cellH` 벽에 부딪히므로 **공용 수정이 이미 진행 중일 수 있다.**
   P1 을 만들기 전에 Discord 에 물어본다
3. **상표** — 공식 한국어 포켓몬명은 포켓몬코리아 상표다. 영문명은 사용자 ROM 에서 런타임
   추출이라 배포물에 없지만 **한국어명은 모드에 담긴다.** 개인 빌드는 무관, 공개 시 검토
4. **번역 키가 영문 원문** — 업스트림이 영어 한 줄만 고쳐도 해당 번역이 orphan 이 된다.
   자동 업데이트가 켜져 있으면 **조용히 영어로 되돌아간다.** `--refresh` 재동기화 절차 필요
5. **인라인 대사 오버라이드의 취약성** — `Commands.lua:81-87` 이 map-scope 먼저 조회 후
   영문 리터럴로 폴백한다. 키가 맥락에 따라 달라지고 공백 편집에 깨진다
